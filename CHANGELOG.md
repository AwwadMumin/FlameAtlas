# Changelog
Contract changes after Phase 2 must be listed here and in `docs/API_CONTRACT.md`.

## 1.5.0

- `GET /api/materials` (all materials). `ExperimentListItem` gains `quality_flags` and `flammability_relevant`.
- `POST /api/admin/labels` requires header `X-Admin-Token` when `ADMIN_TOKEN` is set (human labels drive the red banner, so the public deployment must set it).

## 1.4.0

- New endpoints for the frontend (`src/components/api.ts`): `GET /api/experiments`, `POST /api/compare`, `POST /api/ask`. Additive; nothing existing changed.
- **Compare agent**: deterministic comparability rules (smoke, no outcome, different material, different quantity or unit as printed, LOI vs MOC/ULOI never mixed) plus listed differences (gravity, O2, pressure, airflow, procedure, variant, campaign). Optional LLM only phrases the summary and is number-checked (`summary.check_free`); otherwise a template.
- **Ask agent**: vector retrieval over evidence cards (cut-off `ASK_SIMILARITY_THRESHOLD` 0.70), conditions parsed from the question are used only to filter/rank; no match returns "No direct evidence". Moon/Mars questions get an explicit limitation.

## 1.3.0

- Production image is self-contained (`data/`, `docs/`, embedding model baked in); `docker build -f backend/Dockerfile .` from the repo root. Compose builds the same way.

- Human labels moved from `data/derived/outcome_labels.json` to the MongoDB collection `outcome_labels` (atomic upsert per experiment_id). The validation result is stored in `derived_docs`; the `.json`/`.md` files are exported best-effort. `correction.measured_error()` reads the database. No API change. Any old label file must be re-imported with `import_labels.py`.

## 0.1.0 — Phase 0
- Contract, Pydantic models, example responses (generated from the real data by `backend/scripts/build_examples.py`), `MOCK=1`, `/api/health`.

## 0.2.0 — Phase 2
- Real implementations: presets, materials (search/detail/evidence), assess, experiments, about. `MOCK=1` still serves examples.
- Added `MaterialMatch.confident` (bool). `false` = suggestion only; /api/assess never auto-resolves on it. Material resolution: exact (EN/AR normalised) -> Mongo text (token-verified) -> vector (auto-resolve only at >= 0.80).
- 1g MOC threshold rows have `oxygen_pct = null`; for matching, their O2 coordinate is the MOC value (`outcome_value`). Stated in `nearest_evidence[].note`.
- `evidence_groups[].total_in_group` counts all rows near the point, including `tested_at` (conditions_only) rows; the `EVIDENCE` verdict counts only rows with an outcome (`verdict_reason`).

## 0.3.0 — Phase 3 (no schema changes)
- `earth_vs_space`: red banner / `one_g_not_conservative` computed ONLY from human-confirmed `sustained_burn` labels (data/derived/outcome_labels.json); `null` = undetermined (no confirmed labels), `false` = labels exist and none below the lowest pressure-compatible 1g MOC. `comparison_text` reports the MOC range (min..max with sources), never a cherry-picked value.
- Correction module (`services/correction.py`, `correction_models.yaml`): ships `not_configured`, no coefficients. When configured it needs citation/page/equation/formula/inputs/coefficients/valid_range; evaluates only inside `valid_range`; returns `MODEL_ESTIMATE` only if the leave-one-out error exists in `data/derived/validation.json` (Phase 5). Moon/Mars never get an estimate.
- Unknown material: Van Krevelen 1g LOI (17.5 + 0.40·CR, constants in config) labelled "not tested"; user LOI shown as given (needs a test standard) and never compared to MOC; same-family neighbours' nearest evidence; verdict always `NO_DIRECT_EVIDENCE` (a correction model needs a 1g MOC of the same material).

## 0.4.0 — Phase 4 (contract additions only)
- `GET /api/demo-scenarios` is real: 4 scenarios (`pmma_iss`, `sibal_iss`, `pet_exploration`, `unknown_mars`), values taken from the mission presets. Each `request` can be POSTed to `/api/assess` unchanged.
- `scatter_points` now also contains the 1g MOC thresholds (`gravity: "1g"`, `outcome: "MOC threshold (1g, upward)"`, `o2` = the MOC value). The requested point is always exactly one point with `is_requested_point = true`.
- `/api/assess` returns 422 `validation_error` for an unknown `preset_id` (details list the allowed ids) and for a blank `material_query`.
- `docs/examples/*` are regenerated from the real pipeline (`scripts/export_live_examples.py`); new example `assess_sibal_iss.json`. `docs/postman_collection.json` generated by `scripts/build_postman.py` (variable `baseUrl`).

## 0.5.0 — Phase 5 (additive)
- `GET /api/admin/labels/queue?status=pending|unlabelled|suggested|confirmed|all&limit&offset`: items add `suggested_quote` (verbatim sentence the keyword rule matched), and for confirmed items `label`, `quote`, `labelled_by`. Suggestions are computed on the fly and are hints only; they are never saved and never counted.
- `POST /api/admin/labels`: stores a `confirmed` record in `data/derived/outcome_labels.json` (atomic write, upsert by `experiment_id`). 404 unknown id; 422 if the record is not a BASS record with notes, the label is not one of the six values, or `quote` is not a verbatim span of `flame_behavior_notes`. CSV: `python scripts/import_labels.py labels.csv` (template: `--export-queue queue.csv`).
- `GET /api/validation` (+ `scripts/build_validation.py` -> `data/derived/validation.json`, `validation_report.md`): `old_method_test` reports two strengths that are never blended: STRICT (beyond every pressure-compatible 1g MOC row) and VARIANT-DEPENDENT (beyond some rows). Fields: `n_burn_below_moc`, `n_burn_below_moc_variant_dependent`, `n_nonburn_above_moc`, `n_nonburn_above_moc_variant_dependent`, `per_material[]`, `cases[]` (each with quote, both source URLs, `strength`, `moc_range_pct`). Saffire pairs (9) always shown. `correction_model`: status + n_pairs/MAE/max error when configured.
- `GET /api/coverage/{material_id}`: `pressure_axis` has a 5th entry `"not stated"` (records without a pressure cannot be placed in a pressure bin); grids are `grids[gravity_bucket][pressure_idx][o2_idx] = {outcomes, conditions_only}`; `preset_overlays[]` give indices + cell counts. 1g MOC rows are placed at O2 = the MOC value.
- `GET /api/next-experiments?preset=&limit=`: "Suggested test (not a result)"; solids only; empty µg-outcome cells within ±3 O2 bins of a preset's own pressure bin, ranked 0.5·closeness + 0.3·materials affected + 0.2·(1g exists, µg does not). Weights are in config.
- Record `display_text` now appends the verbatim note when a measured row has no numeric value (Saffire).

## 0.6.0 — Phase 6 (additive)
- Optional LLM summary (`services/summary.py`). Used only when `ANTHROPIC_API_KEY` is set, `use_llm` is true (new optional request field, default true) and MOCK is off. Model `claude-opus-5-5` (env `LLM_MODEL`), effort `low`, server-side refusal fallback on.
- The text is accepted only if it passes the guard: every number exists in the context given to the model (record fields, request values, tolerances, counts in `verdict_reason`); no spelled-out numbers; identifiers containing digits must exist in the context; the verdict label is stated; an estimate is labelled "not tested". Otherwise `summary_source = "template"` and the new field `summary_fallback_reason` says why. Refusal, `max_tokens`, timeout and any API error also fall back; assess never fails because of the LLM.
- `AssessResponse.summary_fallback_reason` (string | null): set only when an LLM attempt was rejected or failed.

## 1.0.0 — Phase 7 (no contract changes)
- `docker compose up --build` now loads and embeds the data automatically (one-shot `loader` service, `--if-empty` makes later starts a no-op).
- `/api/health`: `embedding_model.loaded` reports the real state.
- README (architecture diagram, run in 3 commands, rules, workflows, limits), `docs/PROVENANCE.md` (generated by `scripts/build_provenance.py`), latency test (p95 <= ~100 ms on the demo scenarios; budget 1.5 s).

## 1.1.0 — raw sources, Link 2018 tables, honest 1g baseline (additive)
- `data/raw/` + `MANIFEST.json` (url, sha256, date per file) and `backend/scripts/fetch_raw.py`: NASA NTRS (Hirsch 2011 WSTF paper, BASS-II Summary Report TM-20210011385), the Link et al. 2018 supplementary PDF (CC BY 4.0) and the PSI experimental tables. Large files are git-ignored; the manifest is tracked.
- `backend/scripts/parse_link2018.py` -> `data/derived/link2018_S1_S2.csv/.json`: Table S1 (52 microgravity step rows, 19 samples) and Table S2 (46 1g rows, 9 with '-' = no value reported). Position-based parsing with consistency checks; tests compare hand-read cells. Printed Vf units are kept as printed (the right-hand S1 header says mm/s, the left cm/s: unresolved, flagged, not converted). NOT yet loaded into MongoDB.
- WSTF rows verified: all 59 (MOC, ULOI) pairs appear in their Hirsch 2011 table sections.
- 1g baseline is now split by test procedure: each `earth_vs_space.baseline_1g.moc_values[]` has `procedure` (`standard` | `non_standard` | `not_stated`) and `configuration`; new `baseline_1g.standard_moc_values[]` and `procedure_note`. `standard` only when the row's configuration says chemical igniter or standard mounting (Hirsch: chemical igniters were standard; 6-in criterion unless studying pass/fail length); hot-wire, exposed-edge and 1-in/2-in rows are `non_standard`; silence is `not_stated`, never assumed standard.
- `comparison_text` quotes the standard-procedure MOC first (PMMA: 19.0 % O2) and then the range over all configurations (14.0-21.0 %), instead of "depending on variant/pressure".
- Banner (`one_g_not_conservative`) now compares with the standard-procedure MOC when one exists (else the lowest row, and says so).
- `/api/validation`: new `n_burn_below_standard_moc` / `n_nonburn_above_standard_moc`; "variant-dependent" is now explained as configuration-dependent (key names unchanged).

## 1.2.0 — Link 2018 tables loaded as a new source (additive)
- 98 new records (52 microgravity from Table S1, 46 normal-gravity from Table S2; `evidence_type: solid_burn_test`, PMMA rods, `license: CC BY 4.0`, DOI link) merged at load time: base 872 + 98 = 970. IDs: `LINK2018-S1-<sample>-<step>`, `LINK2018-S2-<L|R><nn>`. Builder: `backend/scripts/build_link2018_records.py`; merge + cards + PMMA variants/DOI: `app/services/extra_sources.py`, `scripts/load_to_mongo.py` (`--no-extras` loads the 5 base files only).
- Spread rates are stored exactly as printed (`outcome_unit` "x10^-3 cm/s (as printed)"); the unresolved S1 right-block unit (mm/s) is flagged on every affected row. S2 '-' becomes `conditions_only` ("tested at, no value reported"), never an outcome. Pressure is not stated in the tables, so it stays null. Colour only from the caption (B black, C clear); other prefixes "not stated".
- Loader safety: a non-local MongoDB host requires `--confirm-drop`. New `docs/DEPLOY_DB.md` (Atlas steps; why not Supabase).
- Tests read expected sizes from the data files (`tests/helpers.py`) instead of hard-coded 872/31.
- `comparison_text` shows a measured spread rate (variable, value, unit) when a record has one, instead of "observations recorded".
